# Master prompt — «Неси Брейнрот»

## Роль

Ты — lead gameplay/web graphics engineer. Разрабатывай этот проект как полноценную WebGL-first 3D-демку для GitHub Pages. Работай только с актуальным `main` репозитория `amazin20/nesi-brainrot`; старые ZIP, старые ветки и 2D/placeholder-рендер не использовать.

## Главная цель

Собрать короткий, но законченный 3D-вертикальный срез: игрок подбирает брейнрота на стартовой площадке, проходит небесную полосу препятствий с грузом, активирует чекпоинты и доставляет груз к финишному флагу. Результат должен открываться по прямой ссылке GitHub Pages и запускаться в браузере с включённым WebGL без установки дополнительных программ.

## Жёсткие ограничения

1. Рендеринг — только Three.js/WebGL. Никаких 2D canvas-режимов, плоских скриншотов, HTML-заглушек или процедурного персонажа вместо GLB.
2. Все десять оптимизированных GLB должны лежать в `public/models`, входить в production-сборку и загружаться через `GLTFLoader` + `DRACOLoader`.
3. Проект должен быть статическим: без сервера, базы данных и обязательной авторизации.
4. Любая ошибка загрузки отдельной модели должна показываться в консоли и локально заменяться простой 3D-геометрией только для продолжения сцены; сама модель не должна silently пропадать.
5. Любое изменение обязано проходить `npm run test` и `npm run build` до публикации.

## Обязательный игровой цикл

- Экран загрузки с прогрессом десяти GLB.
- Стартовый экран с целью и подсказками управления.
- Трёхмерная сцена: небо, туман, свет, частицы, платформа и трасса.
- Подбор груза, переносимый объект прикрепляется к персонажу.
- Пять читаемых секторов: маятники, батуты, роллер, барьеры, небесные острова.
- Кинематический контроллер: WASD/стрелки, прыжок Space, гравитация, ускорение и торможение.
- Удар от препятствия и падение возвращают к последнему чекпоинту.
- Два чекпоинта сохраняют прогресс текущего забега.
- Финиш засчитывается только с грузом; экран победы показывает время и рекорд.
- `R` перезапускает забег, `Esc` и кнопка HUD ставят игру на паузу.
- На сенсорных экранах доступны джойстик и кнопка прыжка.

## Качество и UX

- Стилистика: яркий неоновый небесный фестиваль, контрастные материалы и понятная телеграфика опасностей.
- Камера плавно следует за игроком и показывает ближайшее препятствие.
- HUD всегда показывает цель, груз, таймер, прогресс и чекпоинт.
- Никаких пустых экранов после успешной загрузки: либо открывается 3D-сцена, либо показывается понятная ошибка о необходимости включить WebGL.
- Ассеты используют относительный `BASE_URL`, чтобы прямое обновление GitHub Pages не ломало пути.

## Definition of done

Работа считается завершённой, когда одновременно выполнены все условия:

1. `npm run test` проходит без ошибок.
2. `npm run build` проходит без ошибок, а `dist/models` содержит все десять GLB.
3. GitHub Actions успешно выполняет build и deploy jobs.
4. GitHub Pages отдаёт production-ассеты, а не исходный `src/main.js`.
5. В браузере с WebGL появляется настоящая Three.js-сцена; 2D-режима в коде нет.
6. Репозиторий содержит README, это ТЗ и ссылку на игру.

## Следующий порядок работ

1. Проверить актуальные файлы и ассеты на `main`.
2. Проверить загрузку GLB и отсутствие 2D/placeholder-веток.

4. После каждого milestone запускать тесты, сборку и GitHub Pages deploy.
5. Отчитываться только о подтверждённых результатах и отдельно отмечать ограничения среды предпросмотра.
